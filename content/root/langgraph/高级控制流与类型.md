欢迎来到 **第四阶段：高级控制流与类型 (Advanced Control)**。

在之前的阶段，我们的图结构是“静态”的：所有的边（Edges）和节点（Nodes）在编译时就已经固定好了。虽然我们可以用条件边（Conditional Edges）做一些路由，但如果想要更灵活的控制——比如在节点内部直接决定“跳到哪里”，或者动态生成并行的子任务——就需要这一阶段的工具。

核心文件是 `langgraph/types.py`，它定义了三个强大的控制原语：`Command`, `Send`, 和 `interrupt`。

## 1. Command：节点手中的指挥棒

在标准模式下，节点只能返回状态更新（`update`），而流向是由图的边（Edges）控制的。`Command` 允许节点同时控制 **状态更新** 和 **控制流向**。

- **作用**: 你可以在节点内部直接告诉引擎：“更新这些状态，并且**立刻**跳转到节点 X（无视原本定义的边）”。
    
- **优势**: 减少了为了路由而专门编写“条件边”函数的样板代码。
    

**代码示例：结合状态更新与跳转**

```Python
from typing import Literal
from langgraph.types import Command
from langgraph.graph import StateGraph, START

# 假设 State 是 {"count": int}

def dynamic_node(state):
    current = state["count"]
    if current > 10:
        # 情况 A: 更新状态并结束
        # goto=END 等同于流向结束
        return Command(update={"count": current}, goto="__end__")
    else:
        # 情况 B: 更新状态并跳转回自己（循环）
        # 这在实现重试或循环逻辑时非常有用
        return Command(
            update={"count": current + 1},
            goto="dynamic_node" 
        )

builder = StateGraph(dict)
builder.add_node("dynamic_node", dynamic_node)
builder.add_edge(START, "dynamic_node")
# 注意：这里不需要 add_edge("dynamic_node", ...) 因为 Command 接管了流向
```

## 2. [[Send：动态并行]] (Map-Reduce)

如果你在运行时有一个列表（比如“5个待处理的文件”），你想同时并行处理它们，但你在写代码时不知道列表有多长，该怎么办？

`Send` 用于实现 **Map-Reduce** 模式。它允许你从一个节点“分发”出多个并行的任务到另一个节点。

- **机制**: `Send("target_node", arg)` 会创建一个新的任务。如果你返回一个 `Send` 列表，LangGraph 会并行运行它们。
    
- **注意**: 这里的 `arg` 是传递给目标节点的**私有输入**，通常不同于共享的全局状态。目标节点通常需要定义一个独立的输入 Schema。
    

**代码示例：动态并行处理**

```Python
from langgraph.types import Send
from typing import Annotated
import operator

# 主状态
class OverallState(TypedDict):
    subjects: list[str]
    jokes: Annotated[list[str], operator.add] # 聚合结果

# 子任务状态（通常不同于主状态）
class WorkerState(TypedDict):
    subject: str

def supervisor(state: OverallState):
    # Map 步骤：为每个 subject 生成一个并行的 generate_joke 任务
    return [
        Send("generate_joke", {"subject": s}) 
        for s in state["subjects"]
    ]

def worker(state: WorkerState):
    # Worker 接收的是 {"subject": "..."}
    return {"jokes": [f"Joke about {state['subject']}"]}

builder = StateGraph(OverallState)
builder.add_node("supervisor", supervisor)
builder.add_node("generate_joke", worker)

# 使用 add_conditional_edges 注册 Send 逻辑
# 当 supervisor 返回 Send 列表时，引擎会自动调度
builder.add_conditional_edges(START, supervisor)
```

## 3. Interrupt：人机回环 (Human-in-the-Loop)

这是构建 Agent 最关键的功能之一。它允许图在执行中间**暂停**，等待人工输入（如审批、澄清问题），然后从暂停的地方**恢复**。

- **触发**: 在节点内调用 `interrupt(value)`。这会抛出一个异常，挂起执行，并将 `value` 发送给客户端。
    
- **恢复**: 客户端使用 `Command(resume=value)` 重新运行图。
    
- **机制**: 当图恢复时，包含 `interrupt` 的节点会**重新运行**。但这次 `interrupt()` 函数不会暂停，而是直接返回用户提供的 `resume` 值。
    

**代码示例：人工审批**

```Python
from langgraph.types import interrupt

def human_review_node(state):
    print("AI generated:", state['draft'])
    
    # 1. 暂停执行，等待用户输入
    # 第一次运行到这里会停止
    # 第二次运行（恢复）时，user_feedback 会等于 Command(resume=...) 里的值
    user_feedback = interrupt("Please review the draft")
    
    if user_feedback == "approve":
        return {"status": "published"}
    else:
        return {"status": "rejected", "reason": user_feedback}
```

**客户端如何配合恢复：**

```Python
# 1. 第一次运行，遇到 interrupt 暂停
for event in graph.stream(input_data, config=thread_config):
    pass 
    # event 会包含 __interrupt__: (Interrupt(value='Please review...'),)

# 2. 用户看了一眼，决定批准
# 使用 Command(resume=...) 恢复执行
graph.stream(
    Command(resume="approve"), 
    config=thread_config
)
```

## 4. 运行时配置 (Runtime Config)

有时节点需要知道“我是谁”或者“现在的配置是什么”（比如获取当前的 `thread_id` 或 `user_id`）。

- **方法**: 在节点函数签名中添加 `config: RunnableConfig` 参数。LangGraph 会自动注入当前的配置对象。
    
- **用途**: 获取 `configurable` 字典中的自定义参数。

```Python
from langchain_core.runnables import RunnableConfig

def node_with_config(state, config: RunnableConfig):
    user_id = config["configurable"].get("user_id")
    thread_id = config["configurable"].get("thread_id")
    return {"log": f"User {user_id} in thread {thread_id}"}
```

## 总结 (Phase 4)

这一阶段赋予了你对图的精细控制能力：

1. **Command**: 将“决策”与“执行”合二为一，实现动态跳转。
    
2. **Send**: 实现“一对多”的并行处理模式。
    
3. **Interrupt**: 暂停程序，引入人类智慧。
    

掌握了这些，你几乎可以构建任何复杂的 Agent 模式。
