| **特性**   | **Event Loop (Asyncio)** | **多线程 (Threading)**           |
| -------- | ------------------------ | ----------------------------- |
| **执行方式** | 单线程，任务间快速切换              | 多线程，由操作系统调度                   |
| **适用场景** | **I/O 密集型** (网络请求, DB)   | I/O 密集型 (但在 Python 中有 GIL 限制) |
| **资源消耗** | 极低 (轻量级协程)               | 较高 (线程上下文切换开销)                |
| **风险**   | 任何一个任务计算太久会卡死所有人         | 需要处理复杂的锁 (Lock) 和竞争条件         |

你可以把 Event Loop 想象成一个无限循环（`while True`），它时刻在做以下三件事：

1. **监控任务**：查看有哪些任务（Task）需要运行。
    
2. **执行任务**：运行当前的任务，直到该任务遇到 `await`（即需要等待 I/O 操作，如读数据库、请求 API）。
    
3. **切换/挂起**：一旦当前任务开始“等待”，Event Loop 会立刻把它**挂起**（暂停），并利用这段等待的空闲时间去执行**下一个**就绪的任务。
