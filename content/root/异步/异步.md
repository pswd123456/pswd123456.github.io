## 📅 第一阶段：坚实的异步基石 (Python Asyncio)

在进入框架之前，必须先理解 Python 的协程（Coroutine）机制，否则很容易写出"假异步"代码。

### 1. 核心概念回顾

- [[进程 线程 协程]]的简介以及占据的资源对比
  
- **[[Event Loop]] (事件循环):** 理解它作为"调度员"的角色。
	它是一个无限循环（`while True`），负责两件事：
	
1. **调度：** 决定现在运行哪段代码。
    
2. **监听：** 监听 网络请求/数据库查询 是否完成
    
- **Keywords:** `async def`, `await`, `asyncio.gather`, `asyncio.create_task`.
    

### 2. 重点攻克：[[Asyncio]].to_thread

这是 Python 3.9+ 引入的神器，用于在异步代码中运行**同步（阻塞）**代码。

- **痛点:** 标准的 `time.sleep()` 或 `requests.get()` 会卡死整个 Event Loop。
    
- **解决:** `asyncio.to_thread` 会自动在独立的线程中运行该函数，而不阻塞主循环。
    
- **练习:** 写一个脚本，同时运行一个 CPU 密集型计算（使用 `to_thread`）和一个 IO 密集型任务（使用 `await`），观察并发效果。

```Python
# 示例：不要让 Pandas 或 Pillow 处理图片阻塞你的 Web 服务
await asyncio.to_thread(sync_blocking_function, arg1)
```

## 🚀 第二阶段：[[高性能 Web 开发]] (FastAPI)

这一阶段的目标是构建一个**全链路异步**的 Web 服务。

### 1. 理解 [[ASGI]] (Asynchronous Server Gateway Interface)

- **概念:** 对比 WSGI (Flask/Django)，ASGI 支持 WebSocket 和 HTTP/2，允许在请求处理中 `await`。
    
- **组件:** 了解 Uvicorn (ASGI Server) 如何与 FastAPI (ASGI App) 交互。
    

### 2. 异步数据库 (Async DB)

> [[greenlet, sqlalchemy, asyncpg]]的简介

这是初学者最大的坑。你不能在 `async def` 的视图函数中使用同步的 PyMySQL 或 psycopg2。

- **ORM 选择:** 学习 SQLAlchemy 2.0 (Async Session) 或 Tortoise-ORM。
    
- **Drivers:** 必须使用异步驱动，如 `asyncpg` (PostgreSQL) 或 `aiomysql`。
    
- **练习:** 配置一个 `AsyncSession`，实现基本的 CRUD。
    

### 3. FastAPI 进阶特性

- **Async Depends (异步依赖注入):** [[FastAPI Depends]] 也可以是 `async def`。常用于异步的数据库连接获取、异步的用户身份验证（调用 Redis）。
    
- **Middleware (异步中间件):**
    
    - 必须使用 `async def dispatch(request, call_next)`。
        
    - 注意：中间件中的耗时操作如果不 `await` 或不放入线程，会拖慢每个请求。

## ⚡ 第三阶段：[[异步任务队列]] (Arq vs Celery)

当任务耗时太长（如视频转码、发送邮件），不能在 HTTP 请求中等待，需要任务队列。

### [[Arq-Redis]] 核心

- **特点:** `arq` 是基于 `asyncio` 和 `redis` 的轻量级作业队列。它原生支持异步函数。
    
- **工作流:** Client 推送 Job -> Redis -> Worker (运行在 Event Loop 中) 消费 Job。


## 作者的理解

### 异步基础
- 首先分清什么是进程, 线程, 协程
	进程具有完整的代码段, 内存分配, 和堆栈, 接受内核级别的调度算法进行调度, 开销很大
	线程管理自己的堆栈, 共享进程代码段和内存分配, 接受内核级别的调度算法进行调度, 开销稍大
	协程可以视作线程中的一个对象, 如何调度由用户自定义, 开销非常小

- python由于全局解释器锁, 无法实现真正的多线程
	就是说, 在CPU密集型的任务中, 事实上不会加快速度
	所以asyncio实际上实现的是单线程多协程IO密集型异步

### fastapi
- fastapi是应用ASGI协议的应用, server是uvicorn, 
	ASGI是一种异步通信的协议, 规定如何打包和接受请求
	uvicorn负责监听和打包请求, 发送给fastapi
	fastapi负责接受请求, 路由到指定入口

### asyncio
- asyncio使用event loop监听异步任务的执行是否成功, 主要使用await挂起协程将控制权交回给event loop 来加入监听队列
	如果是不支持异步的库, 可以使用asyncio tothread加入线程池,
	当同步任务进入线程池时, 如果是CPU密集型任务子线程可能会和主线程争抢GIL导致主线程变慢甚至卡死, 子线程当等待IO时, 会释放GIL, 让主线程的Event loop继续处理其他请求, 

### arq redis
- arq-redis事实上是用redis当作消息中间件, 作为两个进程之间的生产者和消费者的沟通渠道,
	arq作为主进程的单线程多协程的异步IO优化, 内核是asyncio, 实现生产者端的并发, 
	加上redis就实现了进程级并行和单体异步的架构,
	事实上是将cpu密集型任务外包给了其他进程, 目的是不会阻塞主进程的任务
