## response_relevance

- 检查回答和用户输入的问题的关联性
	- 使用生成的回答使用LLM生成几个可能的问题, 默认为三个
	- 将这几个问题在向量空间中检查和原问题的向量关联性
	- 通过公式计算出0-1的分数, 越大越好

## faithfulness

- 检查回答是否基于提取出的答案
	- 根据回答总结出回答的要点
	- 判断以上提取出的要点**能否从**检索中提取出的信息中推断出
	- 按照可以推断出的要点数量除以总的要点数量
	- 通过公式计算出0-1的分数, 越大越好

## context_recall

**注: ragas默认使用LLMbasedContextRecall**

- 关注点在于, 不要遗漏关键的信息
- 检查多大程度相关的内容被成功的检索出来
	- 使用reference(参考答案)作为reference_contexts(检索内容)的代理
		- reference也就是ground_truth
			- 在generator中是LLM直接从问题生成的, 或者是问题集中人工标注的正确答案
	- 总结reference中的要点, 计算有多少要点可以从retrieved_context中推断出
	- 用可以推断出的要点数量除以总的要点数量
	- 通过公式计算出0-1的分数, 越大越好

## context_precision

- 检查检索结果是否能正确的将最相关的回答排在最上面
- 总共返回topk个回答
	- 用加权计算从上至下的回答是否正确
	- 加总后除以相关结果的总数
		- 第一位正确 = 1/1 = 1
			- 第二位错误 -> 0 <- 不相关文档不记入计算中
				- 总分为 1 / 2 = 0.5 <-最终评分
		- 第一位错误 -> 0
			- 第二位正确 -> 0.5
				- 第三位正确 -> 1+0+1/3 = 0.66
				- 0.5+0.66= 1.16/2(只有两个相关文档) = 0.58 <-最终评分
	- 通过公式计算出0-1的分数, 越大越好

### context_entities_recall

依赖LLM提取实体, 也是提两遍算命中率的, 但是这个指标一般都会比较低, 仅供参考, 主要对比趋势

### answer_accuracy

和answer relevancy的区别在于这个是用LLM主观判断, 而不是用答案生成三个问题然后返回向量空间的相似度, 

适合LLM不支持返回n个回答的(比如deepseek), 

以及模型有特定缺陷导致无法在严格prompt条件下用略高temperature(0.3)会输出乱码的问题(比如qwen系列)
