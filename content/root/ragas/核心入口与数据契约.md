这是 Ragas 源码解读的第一部分：**核心入口与数据契约**。

这一部分的目标是解决使用者最常见的问题：“**我应该传什么样的数据给 Ragas？**” 以及 “**`evaluate` 函数到底对我的数据做了什么？**”。

我们将深入阅读 `ragas/dataset_schema.py` 和 `ragas/evaluation.py`。

---

## 1. 数据契约：`ragas/dataset_schema.py`

这个文件定义了 Ragas 如何“看待”你的数据。如果你经常遇到 `ValidationError` 或者指标计算结果为 0/NaN，通常是因为你的数据不符合这里的定义。

### 核心类：`SingleTurnSample`

这是 Ragas 2.0+ 处理单轮对话（最常见场景）的基本单元。请看源码定义：

```Python
# 位于 ragas/dataset_schema.py

class SingleTurnSample(BaseSample):
    """
    Represents evaluation samples for single-turn interactions.
    Attributes
    ----------
    user_input : Optional[str]
        The input query from the user.
    retrieved_contexts : Optional[List[str]]
        List of contexts retrieved for the query.
    reference : Optional[str]
        The reference answer for the query.
    response : Optional[str]
        The generated response for the query.
    ...
    """
    user_input: t.Optional[str] = None
    retrieved_contexts: t.Optional[t.List[str]] = None
    reference_contexts: t.Optional[t.List[str]] = None
    retrieved_context_ids: t.Optional[t.List[t.Union[str, int]]] = None
    reference_context_ids: t.Optional[t.List[t.Union[str, int]]] = None
    response: t.Optional[str] = None
    multi_responses: t.Optional[t.List[str]] = None
    reference: t.Optional[str] = None
    rubrics: t.Optional[t.Dict[str, str]] = None
    # ... 其他字段
```

**源码解读与使用建议：**

1. **字段全是 Optional**：你看源码会发现所有字段（如 `user_input`, `response`）都是 `Optional`。这意味着你在构建 `Dataset` 时如果不填某个字段（比如没有 `reference`），Ragas **不会立刻报错**。
    
2. **隐式依赖**：虽然这里不报错，但具体的 Metric（指标）会依赖这些字段。例如 `context_precision` 依赖 `retrieved_contexts` 和 `reference`（或相关标注）。
    *也就是说现在不报错, 但是如果你评估的字段要用到命名对不上跑测试的时候就会报错*

3. **命名严格**：你传入的字典 key 必须严格对应这些变量名（`user_input`, `response` 等）。如果你的数据里叫 `question` 和 `answer`，你需要重命名，或者在 `evaluate` 函数里使用 `column_map`。

例如:

```python
sample = SingleTurnSample(

            user_input=question,

            response=response_text,

            retrieved_contexts=contexts,

            reference=ground_truth

        )
```

### 数据集加载：`EvaluationDataset.from_list`

这是你把自己的数据加载进 Ragas 的入口。

```Python
# 位于 ragas/dataset_schema.py

    @classmethod
    def from_list(
        cls,
        data: t.List[t.Dict],
        backend: t.Optional[str] = None,
        name: t.Optional[str] = None,
    ) -> EvaluationDataset:
        samples = []
        # 自动判断是多轮还是单轮
        if all(
            "user_input" in item and isinstance(data[0]["user_input"], list)
            for item in data
        ):
            samples.extend(MultiTurnSample(**sample) for sample in data)
        else:
            samples.extend(SingleTurnSample(**sample) for sample in data)
        return cls(samples=samples, backend=backend, name=name)
```

**源码解读：**

- 它会遍历你传入的 `list of dict`。
    
- 它会尝试用 `SingleTurnSample(**sample)` 来实例化每一行数据。
    
- **关键点**：如果你的字典里包含 `SingleTurnSample` 定义之外的 key（比如你自己加的 `metadata` 字段），Pydantic 会默认忽略或报错（取决于配置，但 Ragas 这里通常只取它认识的字段）。所以**不要指望 Ragas 会自动透传你所有的自定义字段**到结果里，除非你修改了 Schema。

## 2. 执行入口：`ragas/evaluation.py`

这是整个库的“大脑”。当你调用 `evaluate()` 时，主要发生了三件事：**数据标准化**、**指标校验**、**执行循环**。

### 函数签名

```Python
# 位于 ragas/evaluation.py

def evaluate(
    dataset: t.Union[Dataset, EvaluationDataset],
    metrics: t.Optional[t.Sequence[Metric]] = None,
    llm: t.Optional[BaseRagasLLM | LangchainLLM] = None,
    embeddings: t.Optional[BaseRagasEmbeddings | BaseRagasEmbedding | LangchainEmbeddings] = None,
    # ... 其他参数
    column_map: t.Optional[t.Dict[str, str]] = None,
) -> t.Union[EvaluationResult, Executor]:
```

### 步骤一：数据标准化 (Standardization)

这是很多用户遇到“KeyError”的地方。

```Python
    if isinstance(dataset, Dataset):
        # 1. 映射列名：如果你传了 column_map={"question": "user_input"}，这里会生效
        dataset = remap_column_names(dataset, column_map)
        # 2. 转换格式：处理 v1 版本的数据格式差异
        dataset = convert_v1_to_v2_dataset(dataset)
        # 3. 实例化：将 HuggingFace Dataset 转换为 Ragas 的 EvaluationDataset (即 SingleTurnSample 的列表)
        dataset = EvaluationDataset.from_list(dataset.to_list())
```

**源码启示**：如果你使用 HuggingFace `Dataset` 对象，Ragas 会先把它转成 Python list，再转成 `EvaluationDataset`。如果你数据量巨大，要注意内存开销。

### 步骤二：指标校验 (Validation)

这是 Ragas 防止你“瞎跑”的关键保护机制。

```Python
    if isinstance(dataset, EvaluationDataset):
        # 校验 dataset 是否包含 metrics 所需的所有列
        validate_required_columns(dataset, metrics)
        # 校验 dataset 的类型（单轮/多轮）是否支持所选的 metrics
        validate_supported_metrics(dataset, metrics)
```

**源码启示**： 这里的 `validate_required_columns` 会去检查每个 metric 对象的 `required_columns` 属性（我们在后续第三部分会细读）。如果你的数据集缺列，程序会在这里抛出 `ValueError` 并终止，而不是等到跑了一半才报错。

### 步骤三：初始化与执行 (Execution)

这里解释了为什么 Ragas 可以自动适配 LLM。

```Python

    # 遍历每个 metric 进行初始化
    for i, metric in enumerate(metrics):
        # ...
        if isinstance(metric, MetricWithLLM) and metric.llm is None:
            if llm is None:
                # 如果没提供 LLM，默认使用 OpenAI gpt-4o-mini
                from openai import OpenAI
                client = OpenAI()
                llm = llm_factory("gpt-4o-mini", client=client)
            # 将全局传入的 llm 赋值给每个 metric
            metric.llm = t.cast(t.Optional[BaseRagasLLM], llm)
            llm_changed.append(i)
        
        # 调用 metric 自身的 init 方法，注入 run_config
        metric.init(run_config)
```

**源码启示**：

- **LLM 优先级**：如果你在创建 `Metric` 对象时指定了 `llm`（例如 `Faithfulness(llm=my_llm)`），那么 `evaluate` 函数参数里的 `llm` **会被忽略**（针对该指标）。
    
- **默认行为**：如果你什么都不传，Ragas 会偷偷初始化一个 `OpenAI` 客户端。如果你的环境变量没设 `OPENAI_API_KEY`，这里就会报错。
    

最后，执行部分使用了 `Executor` 并发运行：

```Python
        if sample_type == SingleTurnSample:
            _ = [
                executor.submit(
                    metric.single_turn_ascore, # 调用指标的异步打分方法
                    sample,
                    row_group_cm,
                    name=f"{metric.name}-{i}",
                    timeout=run_config.timeout,
                )
                for metric in metrics
                if isinstance(metric, SingleTurnMetric)
            ]
```

这意味着 Ragas 是**逐行 (Row)**、**逐指标 (Metric)** 并发执行的。

## 总结：第一部分核心知识点

1. **输入数据**：本质是 `SingleTurnSample` 对象的列表。你的数据字典 key 必须对应 `user_input`, `response`, `retrieved_contexts`, `reference`。
    
2. **列映射**：如果在 `evaluate` 之前不想改数据 key，可以使用 `column_map` 参数。
    
3. **报错机制**：如果缺列，`validate_required_columns` 会在运行前拦截；如果字段类型不对（比如 `retrieved_contexts` 应该是 list 却给了 str），`SingleTurnSample` 实例化时会报错。
    
4. **默认 LLM**：如果不指定 LLM，Ragas 默认尝试连接 OpenAI。
