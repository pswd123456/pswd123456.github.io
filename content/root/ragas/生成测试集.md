## Ragas 测试集生成：第三步执行生成 (Execution) 源码解析

这一步是整个流程的“引擎”，它将静态的文档转化为动态的问答对。从源码来看，这个过程比简单的“提问-回答”要复杂得多，它包含了一个完整的**演化（Evolution）**过程。

### 1. 核心入口：`generate` 方法

无论你调用的是 `generate_with_langchain_docs` 还是 `generate_with_llamaindex_docs`，它们最终都会汇聚到类内部的 `generate` 方法。

**源码片段：**

```Python
    def generate(
        self,
        testset_size: int,
        query_distribution: t.Optional[QueryDistribution] = None,
        # ... 其他参数
    ) -> t.Union[Testset, Executor]:
        # ...
        # 1. 准备查询分布 (决定生成什么类型的题目：简单、推理、多跳等)
        query_distribution = query_distribution or default_query_distribution(
            self.llm, self.knowledge_graph
        )
        
        # ...
        # 2. 生成“角色” (Personas)，让问题不仅仅是机器人的语气
        if self.persona_list is None:
            self.persona_list = generate_personas_from_kg(
                llm=self.llm,
                kg=self.knowledge_graph,
                num_personas=num_personas,
                callbacks=callbacks,
            )
```

**解读：**

- **自动化配置**: 如果你没提供 `query_distribution`，Ragas 会根据你的知识图谱自动决定生成各种问题的比例（例如：50% 简单题，30% 推理题）。
    
- **角色生成 (`generate_personas_from_kg`)**: 这是 Ragas 的一大特色。它不仅仅是根据文本提问，还会先根据文档内容生成虚拟的“提问者角色”（例如“高级工程师”、“初级用户”），以增加问题的多样性和真实感。

### 2. 两阶段生成流程 (Two-Stage Generation)

源码显示，生成过程被显式地分为了两个阶段：**生成场景 (Scenarios)** 和 **生成样本 (Samples)**。这是为了保证生成的逻辑性和可控性。

阶段一：生成场景 (Scenarios)

这一步不直接写问题，而是先确定“考点”。

**源码片段：**

```Python
        # new group for Generation of Scenarios
        # ...
        exec = Executor(desc="Generating Scenarios", ...)
        
        # 根据分布比例，计算每种题目要生成多少个
        splits, _ = calculate_split_values(
            [prob for _, prob in query_distribution], testset_size
        )

        for i, (scenario, _) in enumerate(query_distribution):
            exec.submit(
                scenario.generate_scenarios,  # <--- 调用场景生成器
                n=splits[i],
                knowledge_graph=self.knowledge_graph,
                persona_list=self.persona_list[:num_personas],
                # ...
            )
        
        scenario_sample_list = exec.results()
```

**解读：**

- Ragas 使用 `Executor` 进行**并行处理**。它根据 `testset_size` 和分布比例（`splits`），并行地去知识图谱中寻找适合出题的节点组合。
    
- 比如，对于“多跳推理”类问题，这一步会去图谱中寻找两个有连接关系的节点，确立一个“从 A 推导到 B”的场景。
    

阶段二：生成样本 (Samples)

这一步才是真正的“填肉”，将抽象的场景转化为具体的文本。

**源码片段：**

```Python
        # new group for Generation of Samples
        # ...
        exec = Executor("Generating Samples", ...)
        
        for i, (synthesizer, _) in enumerate(query_distribution):
            for sample in scenario_sample_list[i]:
                exec.submit(
                    synthesizer.generate_sample, # <--- 调用合成器生成具体文本
                    scenario=sample,
                    callbacks=sample_generation_grp,
                )
```

**解读：**

- [[synthesizer]]（合成器）接收上一步生成的 `scenario`（场景），利用 LLM 生成具体的：
    
    1. **user_input**: 问题
        
    2. **reference**: 标准答案
        
    3. **retrieved_contexts**: 参考上下文
        
- 这里同样使用了 `Executor` 并行加速，因为这是最耗时的 LLM 调用环节。

### 3. 关键组件：Transforms (转换)

虽然 `transforms` 的应用发生在 `generate` 方法被调用**之前**（在 `generate_with_...` 中），但它是“执行生成”能够成功的基石。

**源码片段 (`generate_with_langchain_docs` 中):**

```Python
        if not transforms:
            transforms = default_transforms(
                documents=list(documents),
                # ...
            )
        
        # ...
        kg = KnowledgeGraph(nodes=nodes)
        
        # apply transforms and update the knowledge graph
        apply_transforms(kg, transforms) # <--- 核心：丰富图谱
        self.knowledge_graph = kg
```

源码对应 (default_transforms):

在 ragas/testset/transforms/default.py 中，我们可以看到默认的转换包含：

- **HeadlineSplitter**: 基于标题切分文档。
    
- **EmbeddingExtractor**: 计算节点嵌入。
    
- **SummaryExtractor**: 提取摘要。
    
- **CosineSimilarityBuilder**: 建立节点间的相似度联系（这对于生成“推理”或“比较”类问题至关重要）。
    

解读：

如果不执行这一步，知识图谱里只有孤立的文档片段。执行 apply_transforms 后，图谱里就有了节点间的关系（Relationships）。这使得 Ragas 能够生成跨文档或跨段落的复杂问题，而不仅仅是针对单一段落的简单提问。

### 总结：作为使用者的关注点

在“执行生成”这一步，源码告诉我们：

1. **并行机制**: Ragas 内部使用了 `Executor` 并行化，所以生成速度主要取决于你的 LLM 并发限制（Rate Limit），而不是本地计算能力。
    
2. **多样性来源**: 数据的多样性来自 **Personas (角色)** 和 **Transforms (图谱关系构建)**。
    
3. **无需干预**: 复杂的两阶段生成（场景 -> 样本）是全自动的，你只需要关心最终结果。
