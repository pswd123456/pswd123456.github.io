## Ragas 测试集生成：第二步数据准备 (Data Preparation) 源码解析

这一步的核心任务是为 `TestsetGenerator` 提供“原材料”。Ragas 并不直接读取 PDF 或 TXT 文件，而是依赖标准化的 **Document 对象**。

### 1. 支持的数据格式

从源码来看，Ragas 设计了两个专门的入口方法来处理数据，分别对应目前最主流的两个框架：**LangChain** 和 **LlamaIndex**。

**源码证据：** 在 `ragas/testset/synthesizers/generate.py` 中，定义了两个并行的方法：

- `generate_with_langchain_docs(...)`
    
- `generate_with_llamaindex_docs(...)`
    

### 2. 源码深度解析：从 Document 到 Node

为什么需要这一步？因为 Ragas 内部并不直接使用 LangChain 或 LlamaIndex 的文档对象，而是通过一个**转换过程**，将它们统一变成 Ragas 内部的 `Node`（节点）对象，存入知识图谱。

我们以 `generate_with_langchain_docs` 为例看源码实现：

**源码片段：**

```Python
    def generate_with_langchain_docs(
        self,
        documents: t.Sequence[LCDocument],  # <--- 1. 输入类型约束
        testset_size: int,
        # ... 其他参数
    ) -> t.Union[Testset, Executor]:
        
        # ... (省略中间代码)

        # 2. 核心转换逻辑：遍历文档，转为 Ragas Node
        nodes = []
        for doc in documents:
            node = Node(
                type=NodeType.DOCUMENT,
                properties={
                    "page_content": doc.page_content, # 取内容
                    "document_metadata": doc.metadata, # 取元数据
                },
            )
            nodes.append(node)

        kg = KnowledgeGraph(nodes=nodes) # 3. 存入知识图谱
```

**解读：**

1. **输入类型 (`documents: t.Sequence[LCDocument]`)**:
    
    - 这里明确要求传入的是一个列表（Sequence），列表里的元素必须是 LangChain 的 `Document` 对象。
      
    - 传入Document chunk时, 可以使用和rag pipeline中一致的chunker和loader, 比如使用了[[docling]]和[[HybridChunker]], 但是要转换回langchain document对象
        
    - 这意味着你不能传字符串列表 `["text1", "text2"]`，必须封装成对象。
        
2. **标准化转换 (`Node(...)`)**:
    
    - Ragas 并不在乎原本是 LangChain 还是 LlamaIndex，它只关心两个属性：**内容 (`page_content`)** 和 **元数据 (`document_metadata`)**。
        
    - `LlamaIndex` 的处理逻辑几乎一样，只是取值字段变成了 `doc.text`。
        
3. **元数据的重要性**:
    
    - 源码中显式地保留了 `document_metadata`。这非常重要，因为生成的测试集中会包含 `filename` 或 `page_number` 等信息，方便你追溯问题来源。
        

### 3. 作为使用者的操作指南

基于上述源码逻辑，你在“数据准备”阶段的代码应该专注于**加载**和**封装**。

**如何构建符合源码要求的输入：**

```Python
from langchain_core.documents import Document

# 方式 A: 手动构建 (适合少量测试数据)
# 对应源码中 doc.page_content 和 doc.metadata 的读取逻辑
doc1 = Document(
    page_content="Ragas 使用大语言模型来生成合成测试数据...",
    metadata={"source": "ragas_intro.pdf", "page": 1}
)

doc2 = Document(
    page_content="TestsetGenerator 是生成模块的核心类...",
    metadata={"source": "ragas_code.py", "type": "code"}
)

documents = [doc1, doc2]

# 方式 B: 使用加载器 (适合批量文件)
# from langchain_community.document_loaders import PyPDFLoader
# loader = PyPDFLoader("my_document.pdf")
# documents = loader.load()
```

### 总结

第二步“数据准备”在源码层面的本质是：**接口适配**。 Ragas 通过 `generate_with_...` 方法充当了“翻译官”，将外部（LangChain/LlamaIndex）的文档格式翻译成内部通用的 `Node` 格式，从而启动知识图谱的构建。你只需要确保传入的数据符合它预期的对象结构即可。
